In Hyprland (version 0.55 and newer), the configuration format has transitioned from the legacy `hyprland.conf` (hyprlang) to native **Lua** configuration (`hyprland.lua`)[1][2]. 

Keybindings and command executions are handled using the built-in Lua API functions, primarily `hl.bind()` paired with dispatcher helpers like `hl.dsp.exec_cmd(...)`[3].

### Basic Syntax for Binds and Executing Commands

According to the Hyprland Wiki, the basic syntax for keybindings takes the form[3]:
```lua
hl.bind("keys", dispatcher_or_function, { bind_flags })
```

To execute external programs or shell commands within a keybind, you should use `hl.dsp.exec_cmd(...)`[3]:

```lua
local mainMod = "SUPER"

-- Bind SUPER + SHIFT + Q to open Firefox
hl.bind(mainMod .. " + SHIFT + Q", hl.dsp.exec_cmd("firefox"))

-- Bind SUPER + Return to open a terminal (e.g., ghostty or kitty)
hl.bind(mainMod .. " + RETURN", hl.dsp.exec_cmd("ghostty"))
```

### Advanced Usage with Anonymous Functions

You can also pass an anonymous Lua function to `hl.bind()` if you need to execute conditional logic or chain multiple dispatchers[3][4]:

```lua
hl.bind("SUPER + SHIFT + X", function()
    -- Custom logic here
    hl.dispatch(hl.dsp.window.float())
end)
```

### Important Warning Regarding Performance
* **Do not block the event loop:** Lua callbacks run directly on the compositor's event loop[3]. Avoid using heavy operations like `io.popen`, synchronous network I/O, clipboard utilities (`wl-paste`, `xclip`), or `sleep` directly inside bind callback functions[3]. 
* Always use `hl.dsp.exec_cmd(...)` for spawning external processes so they run asynchronously outside the critical bind callback path[3].
