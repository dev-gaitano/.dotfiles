In Hyprland's Lua-based configuration system (introduced in version 0.55), **`hl.exec_cmd(cmd, rules)`** (and its dispatcher equivalent **`hl.dsp.exec_cmd(cmd, rules)`**) allows you to execute a shell command while optionally passing a table of window rule effects/parameters to apply to the spawned process[1][2].

### Overview

* **Syntax:** `hl.exec_cmd("command", { rules })` or `hl.dsp.exec_cmd("command", { rules })`[1]
* **Behavior:** It spawns an asynchronous process (using `sh -c`)[1][3]. Unlike the legacy `exec-once` syntax from `hyprlang`, you do not need trailing `& disown` characters[4][3]. 
* **Rules Parameter:** The second argument takes a table of window rule properties/effects to target the resulting window directly[1].

---

### Examples

#### 1. Launching an app on a specific workspace (Silently)
In the Lua configuration, rules like workspace placement can be supplied directly inside the execution command wrapper[5]:

```lua
hl.on("hyprland.start", function()
    -- Launch Thunderbird on workspace 2 silently
    hl.exec_cmd("thunderbird", { workspace = "2 silent" })
end)
```

#### 2. Keybindings with `hl.dsp.exec_cmd`
When binding commands to key combinations, you can pass rules or flags to format how the window behaves upon launch[5]:

```lua
-- Open a floating window with specific dimensions and placement on a workspace via keybind
hl.bind("SUPER + SHIFT + W", hl.dsp.exec_cmd("librewolf --new-window https://www.youtube.com", { 
    workspace = "6 silent", 
    float = true, 
    size = { 1275, 1383 }, 
    move = { 1279, 199 } 
}))
```

*(Note: Depending on how quickly asynchronous apps like Electron/GTK applications start up and request focus, some users manage complex layout positioning via standard global `hl.window_rule` definitions matched by application class, as process-tracking rules via `exec_cmd` can occasionally vary based on application PID behavior)[4][6].*
