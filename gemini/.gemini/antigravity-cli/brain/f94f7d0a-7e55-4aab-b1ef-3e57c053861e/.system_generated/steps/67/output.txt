As documented on the Hyprland Wiki, starting with version 0.55, Hyprland has transitioned from the legacy `hyprlang` syntax (`hyprland.conf`) to a Lua-based configuration system centered around **`hyprland.lua`**[1][2]. 

Because the configuration is a standard Lua file typically located at `~/.config/hypr/hyprland.lua`, you are not forced to put everything into a single massive file[1]. You can split your configuration into multiple separate modules/files and import or load them using Lua's built-in **`require()`** function[1].

### Modularizing your `hyprland.lua` Configuration

You can structure your configuration directory like this:
```text
~/.config/hypr/
├── hyprland.lua
└── configs/
    ├── env.lua
    ├── keybinds.lua
    ├── monitors.lua
    └── windowrule.lua
```

Inside your main `~/.config/hypr/hyprland.lua`, you can pull in these modular files using standard Lua `require`:

```lua
-- ~/.config/hypr/hyprland.lua

require("configs.env")
require("configs.monitors")
require("configs.keybinds")
require("configs.windowrule")

-- Global configuration table using the hl API
hl.config({
    general = {
        gaps_in = 5,
        gaps_out = 10,
        border_size = 2,
        resize_on_border = true,
        layout = "dwindle",
    },
    decoration = {
        rounding = 10,
    },
})
```

### Best Practices & Order of Execution
* **Load Order Matters:** Ensure that environment or utility modules (`require`) are loaded before any other modules that rely on those states or call specific `hl.*` functions[3].
* **File Paths:** Lua’s `require` looks for modules relative to your Lua search paths, or you can require them using relative paths/dot notation depending on how you structure your config directory tree.
