The search query targets documentation, discussions, and dotfiles related to **Hyprland's Lua-based configuration system** (introduced around versions 0.55+), specifically focusing on global functions and namespaces like `hl.config`, `hl.dsp`, and `hyprland.lua`[1][2].

Here is a summary of what these components mean and how they are used in Hyprland's Lua configuration framework:

### 1. `hyprland.lua`
* **What it is:** The native Lua configuration entry point for Hyprland (replacing or running alongside the older `hyprland.conf`)[2]. 
* **Structure:** Users write their configurations using standard Lua syntax, often splitting options into multiple files and bringing them together using `require()`[3][4].

### 2. `hl.config`
* **What it does:** Used to define layout settings, decorations, animations, environment variables, inputs, and general compositor configurations structurally using Lua tables[4][5].
* *Example:*
  ```lua
  hl.config({
      general = {
          gaps_in = 0,
          gaps_out = 5,
          border_size = 2,
          layout = "dwindle",
      },
      decoration = {
          rounding = 10,
      }
  })
  ```[4]

### 3. `hl.dsp` (Dispatchers)
* **What it does:** Represents Hyprland dispatchers[6]. `hl.dsp.*` functions generate description tables of actions you want to perform (such as executing commands, changing focus, resizing, or managing workspaces)[6].
* **Crucial Behavior:** 
  * When used directly inside a keybind declaration (`hl.bind`), they can often be passed directly[7].
  * If you want to use a dispatcher *inside a custom Lua function or event listener*, you must wrap it inside `hl.dispatch()` to execute it[6]. Writing `hl.dsp.whatever()` on its own inside a function will do nothing[6].
* *Example:*
  ```lua
  -- Directly in a bind:
  hl.bind("SUPER + Return", hl.dsp.exec_cmd("kitty"))

  -- Inside a custom function/event wrapper using hl.dispatch:
  hl.bind("ALT + Tab", function()
      hl.dispatch(hl.dsp.window.cycle_next())
  end)
  ```[5][6]
